Twenty Q

Game Web App React Android
Open app

Twenty Q is a twenty questions game that looks and sounds like a 90s handheld toy. You think of something, it asks questions, and it tries to guess what you picked within twenty.

I wanted to build the thing I remember playing: a round plastic gadget with a little green screen and four big buttons, which somehow seemed to read your mind. I wanted to find out how it could work, and then make it small enough to understand end to end.

How it plays

You answer each question with one of four buttons: Unknown, No, Yes or Sometimes. The buttons never change. All the guidance is on the screen, the way it was on the toy. It starts by asking whether your thing is an animal, a vegetable or a mineral, and those count as questions too. Then it asks about things like size, colour, where you find it and what it is made of. From turn 8 it will guess once it is confident enough, and from turn 20 every turn is a guess. If it misses at 20, it gets five more.

How it picks a question

Behind the screen is a hand-built knowledge base of 994 things and 168 questions. For every thing it holds an answer to every question: yes, no, sometimes, or unknown. After each of your answers it nudges the odds of every thing up or down rather than crossing anything off, so one wrong answer from you does not end the game.

To choose the next question it works out which one would split the remaining possibilities most evenly, which is the same idea as the classic information gain measure. It picks from the best three rather than always the single best, so two games about the same thing do not run the same way.

What I checked, and what that does not show

I wrote a script that plays the game itself, once for every thing in the knowledge base, five times each. When it answers truthfully, the app guesses correctly within twenty questions 98.6% of the time. When one answer in ten is deliberately wrong, it still gets there within twenty five turns 92.7% of the time.

Those numbers come from a simulated player that answers from the same knowledge base, so they show that the engine is consistent, not that every real person would answer every question the way I did. The real test is whether it can guess your thing, and when it cannot, that usually points at an answer I got wrong in the knowledge base.

What it does

  • Plays like the toy. A round shell, a dot matrix screen that types out its questions, four fixed buttons, undo, and small synthesized beeps you can mute.
  • Works offline. The questions and the knowledge base are built in. There is no server, no account and no analytics.
  • Keeps almost nothing. Only your game stats, your sound setting and your theme, stored on your own device.
  • Undo goes back one turn. Including a guess. The game replays from the start, so it picks up exactly where it was.
  • Light and dark, and the keyboard. Answer with U, N, Y and S, undo with Backspace.
  • Fits the screen. It scales from a small phone to a large desktop window without scrolling.

How it's built

The web app is React, TypeScript and Vite. The guessing engine is a small piece of plain TypeScript with no screen code in it, which is what let me test it on its own. It is a pure function of the knowledge base, a random seed and your answers, so undo is just replaying the game with one answer fewer.

There is also an Android version, built on the same knowledge base and the same engine rules. Android app coming to Google Play. The web version is the reference for both.

The honest caveat

It is a game, not a mind reader. It knows 994 things, so if you think of something outside that list it can only guess the nearest thing it knows. It does not learn from its misses, and I would rather say so than imply it does.
